## Approved Boundary

```text
Input Identity
      ↓
C# Product Version Identity
      ↓
Execution Identity
      ↓
Result Identity
      ↓
Evidence Reference
```

A logical Result Package reference may be included as a read-only link. It does not establish a file format、API、database or serialization commitment.

## Included Identity

| Layer | Included Phase-1 Identity | Authority／Source |
|---|---|---|
| Input Identity | `LayoutRequest.Id`; Geometry／Axis／Module request and object identities; selected Partition | Existing typed C# request contracts |
| C# Product Version | Repository commit or approved Product build identity | C# Mainline／release evidence |
| Execution Identity | One bounded `LayoutEngine.Generate` execution reference and validation／terminal status | C# Runtime workflow |
| Result Identity | `LayoutResult` request、partition、status、panels、capacity、count、warnings and errors | C# Mainline Product result |
| Evidence Reference | C# test、Golden scenario／manifest／hash、Python report fingerprint when used、PM decision reference | Evidence chain; no authority transfer |
| Logical Result Package | Reference to read-only package／review identity | No recalculation and no binding API／schema |

## Explicit Exclusions

- Canonical Project Model。
- Project lifecycle database。
- API platform。
- Cloud persistence or service。
- UI state。
- Domain-specific lifecycle semantics。
- Full CAD／GIS document lifecycle。
- Consumer recalculation、repair or reinterpretation of Product values。

## Boundary Rules

- Each included field must map to an existing C# input、Product result or immutable Evidence reference。
- Missing identity is reported as an Evidence gap; it is not generated by fallback inference。
- Python may verify references and consistency only。
- Expanding beyond this boundary requires separate authority and is not part of Candidate A。
